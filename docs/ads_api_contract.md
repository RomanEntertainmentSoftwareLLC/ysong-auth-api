# Ads campaign API contract (v1)

Ads uses the existing Promotion tables and authenticated `/api/tools/promotion` router. The new `/ads/campaigns` surface is a small product contract over `promotion_ad_campaigns`; it does not own a second campaign, destination, creative, audio, or analytics store. All routes require the same `requireAuth` owner check as Promotion.

## Routes

| Method | Path | Result |
| --- | --- | --- |
| GET | `/ads/campaigns` | `{ campaigns: AdsCampaign[] }`, newest updates first |
| GET | `/ads/campaigns/:id` | `{ campaign: AdsCampaign }` or 404 |
| POST | `/ads/campaigns` | Create a local draft from `AdsDraft`; returns `{ campaign }` (201) |
| PATCH | `/ads/campaigns/:id` | Merge draft fields; returns `{ campaign }`. Only local `draft`, `ready`, or `failed` campaigns without a remote campaign can be changed (409 otherwise). |

`AdsDraft` has `smartLinkCampaignId`, `name`, `goal`, optional `sourceTrackId`, `genre`, `genreSource`, `dailyBudget: { minor, currency }`, `schedule: { start, end, timezone }`, `placements: [{ channel, surface }]`, `audience: { countries, ageMin, ageMax, gender, interestRefs: [{ id, name }] }`, and `copy: { text, headline, language }`. It also accepts nullable wizard selections: `selectedReleaseId`, `verifiedAudioReferenceId`, `creativeId`, `destinationId`, `connectedAssets: { connectionId, businessId, adAccountId, pageId, instagramUserId, pixelId }`, and `estimatedAudience: { source, kind, ready, estimate, lower, upper, targetingStatus, capturedAt }`. `channel` is `facebook` or `instagram`; `surface` is `feed`, `reels`, or `stories`. Budget is in the currency's minor units. A schedule needs both dates, with end after start. POST requires only `smartLinkCampaignId`; unset name, budget, and placement receive local draft defaults. Unknown fields, including provider submission objects and access tokens, are rejected. PATCH merges the nested budget, schedule, audience, and copy objects; it cannot change the Smart Link owner. Send `null` to clear a wizard selection.

The selected release must be the Smart Link's release. The audio reference must be an owned, published YSong track with stored audio from that release; this validates the reference record, while acoustic matching remains the separate trusted audio match service. A creative must belong to this Ads campaign, and a destination must belong to its Smart Link. Connected asset IDs must match the user's current Meta asset selection when saved. Only IDs are stored in the draft; credentials remain in the Meta connection store. The audience snapshot is display metadata, not publish authority. Changing targeting, placements, or connected assets through PATCH clears the old snapshot unless a replacement is supplied. The API derives submission state from the Promotion campaign and its Meta publish fields, so clients cannot set it through draft writes.

`AdsCampaign` contains the draft fields plus `id`, local `status`, `sourceReleaseId`, `audioSnippetIds`, `creativeRefs` (`id`, `status`, `selected`, `audioSnippetId`), Smart Link `destinations` (`id`, `platform`, `label`, `url`, `kind`, `enabled`, `position`), `metaSubmission` (`state`, `submittedAt`, `hasError`), `delivery` (`state`, `providerStatus`, `checkedAt`, `reasons`, `error`), `review` (`state`, `checkedAt`), `analytics` (`href`, `attributionCampaignId`, `smartLinkCampaignId`), and `provenance` (`origin`, `ownerUserId`, `genreSource`, `createdAt`, `updatedAt`). Submission state is `not_submitted`, `submitting`, `submitted`, or `failed`. Delivery state is `not_submitted`, `submitting`, `submitted`, `in_review`, `active`, `paused`, `rejected`, `failed`, or `archived`. `submitted` means Meta creation completed but delivery has not been confirmed. `active` requires an active campaign, ad set, and ad in a provider refresh. Review state is `not_requested`, `pending`, `approved`, `rejected`, or `unknown`; paused remote campaigns with no review evidence are `unknown`. Provider issue messages appear in `delivery.reasons`; submission errors appear in `delivery.error`.

`sourceReleaseId` comes from the linked Smart Link's `world_releases` reference; `sourceTrackId` and `audioSnippetIds` point to existing YSong master/snippet records. `creativeRefs` point to existing rendered creatives. Destinations are owned by the Smart Link and edited through its existing campaign routes. Analytics remains at the `analytics.href` route and joins Meta snapshots with first-party Smart Link attribution. The API does not copy or embed media, insights snapshots, Meta object IDs, account credentials, or Graph payloads in this contract.

Draft creation and editing do not submit ads or authorize spend. The existing `/ad-campaigns/:id/meta/preflight`, `/meta/publish`, `/meta/refresh`, `/meta/status`, and `/meta/discard` routes retain review, explicit confirmation, remote operations, and provider details. Refresh is safe to repeat and updates delivery and review evidence without creating a remote ad. A failed or rejected submission cannot be blindly published again: if Meta created a campaign, explicitly discard it before preflight and resubmission. An incomplete creation remains locked for reconciliation; refresh and pause remain available. Existing `/ad-campaigns` responses remain available for current clients. The runtime Promotion schema extends the local status constraint for `submitted` and `rejected`.

## Smart Link attribution

The authenticated `GET /ad-campaigns/:id/analytics` response also contains `normalized`, a read model with `campaign`, `creatives`, `destinations`, and `destinationVariants` rows. Each row identifies the local campaign, creative, destination, and variant where applicable. Provider fields are `spend`, `impressions`, `reach`, `clicks`, `ctr` (percent), `cpc`, and `cpm`; first-party fields are `smartLinkClicks` and `conversions`. `conversions` counts attributed YSong conversion events at campaign and creative level. Destination conversion attribution is unavailable. No provider spend or impressions are assigned to Smart Link destinations or variants. Creative reach is unavailable when several Meta ads map to one creative because reach cannot be added across ads.

`null` means a metric was missing, could not be attributed, or has no valid denominator; an observed zero stays `0`. A creative missing any expected Meta ad report has null provider metrics. The currency is the campaign currency verified against the Meta ad account at preflight, and `sources.provider` includes the snapshot capture time, staleness, currency, and Meta reporting dates. Each campaign or creative row retains its provider reporting dates when available. `sources.smartLink` records the inclusive first-party query dates. The older `meta`, `ysong`, and `derived` response fields remain available for existing clients.

The public redirect `/api/promotion/r/:slug/:destinationId` accepts optional `ac` (Ads campaign UUID), `cr` (creative UUID), and `dv` (destination variant label), plus `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, and `utm_term`. The landing page may pass the same values as `ysong_ad_campaign`, `ysong_creative`, and `ysong_destination_variant`; public event and fan bodies may use camel-case field names. Keep the destination ID in the path. Ads may use a distinct `dv` for each placement or destination test without creating another destination record.

The API records only bounded, plain-text attribution labels and verifies that an Ads campaign belongs to the Smart Link and a creative belongs to that Ads campaign. Invalid identifiers are ignored. Query parameters are never appended to the destination URL. Do not put tokens, email addresses, or other secrets in attribution labels or destination URLs. Campaign and paid analytics attribution rows include the destination ID and aggregate click counts grouped by creative, destination variant, and UTM fields. Paid analytics also lists destination variant rows under each creative while keeping creative and destination totals aggregated; destination totals count distinct visitors across variants. Cloned variants may share one creative ID and use distinct `dv` labels for descriptive comparisons. These counts do not imply a randomized or statistically valid A/B test. Redirects keep their existing 302 target and destination ID behavior.
