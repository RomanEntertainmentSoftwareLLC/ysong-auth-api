# Ads audio-to-release match service (v1)

`matchAdsAudioToRelease(input)` in `src/promotion/audio-release-match.mjs` is a pure service boundary. A trusted caller provides the Ads upload fingerprint, authorized YSong master/reference or artist-supplied reference fingerprints, optional comparator results, and supporting release metadata. It returns `{ outcome, confidence, referenceId, referenceSource, reasons }`. The module does no network or media retrieval. In particular, streaming destinations are not reference audio sources and protected masters must never be fetched from a streaming service.

Fingerprints have `algorithm`, opaque `value`, and `durationSeconds`. Exact values are compared only when algorithms agree. `comparisons` contains trusted precomputed `similarity` (0–1) and `overlapSeconds` for a named reference; a public request must not be allowed to supply these scores as trusted evidence. The schema rejects unknown fields, duplicate or unknown references, cross-algorithm comparisons, and overlap longer than either audio item. Authorized reference provenance and access control must be established by the caller before invoking this function.

The outcomes are `same_recording`, `likely_same_recording`, `possible_alternate_master_or_edit`, `related_or_different_version`, `mismatch`, and `insufficient_evidence`. Exact fingerprints or high similarity with substantial overlap support a same-recording result. A material duration difference with high similarity indicates a possible edit or alternate master. Moderate similarity indicates a related or different version. A mismatch needs a low similarity score over substantial overlap. Missing, short, or inconclusive acoustic evidence remains insufficient even when ISRC, title, and artist all agree. Confidence is a bounded service assessment, not a calibrated legal probability.

The service selects the strongest acoustic outcome, preferring YSong master, then YSong reference, then artist reference when outcomes tie. A positive artist result can win over a YSong mismatch, and `other_reference_conflicts` flags that disagreement. Metadata appears as support or conflict reason codes but never promotes a result to an acoustic match. A match does not prove ownership or grant permission to advertise. Use the separate Content Rights Gate for promoted-use authorization.
